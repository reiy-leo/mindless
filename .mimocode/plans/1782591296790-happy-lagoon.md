# Plan: Defer keychain access to actual usage

## Problem
`SettingsPage.tsx:192-204` has a `useEffect([], [])` that eagerly calls `loadPat()` for all 3 providers (github, gitlab, gitee) on mount. This triggers the macOS keychain permission popup whenever the user opens the sync settings tab, even if they don't need to use keychain at that moment.

## Root Cause
```ts
// SettingsPage.tsx:192-204
useEffect(() => {
  ;(async () => {
    const { loadPat } = await import('@/lib/api')
    for (const provider of ['github', 'gitlab', 'gitee']) {
      const pat = await loadPat(domainMap[provider])
      if (pat) results[provider] = pat
    }
    setSyncPats(prev => ({ ...prev, ...results }))
  })()
}, [])
```

## Solution: Lazy keychain loading

### 1. Add `hasPat` flag in localStorage
When saving a PAT via `handleSavePat`, also store a boolean flag `mindless-sync-has-pat-{domain}` in localStorage.

### 2. Remove eager `loadPat` on mount
Replace the `useEffect([], [])` that loads all 3 PATs with one that only checks `hasPat` flags from localStorage (no keychain access).

### 3. Load PAT lazily when needed
In `handleTest`, `handleSync`, and `handleSavePat`: if `syncPat` is empty but `hasPat` flag exists, load from keychain first.

### 4. Update input field display
Show placeholder "••••••••" when `hasPat` is true but PAT is not loaded yet. Load the actual PAT when user focuses the input.
