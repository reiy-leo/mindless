# 修复 Milkdown 多步骤编辑器同时显示多个 toolbar

## 根因分析

经过深入调查 Crepe toolbar 的实现机制，发现根本原因：

1. **每个 editor 有独立的 ProseMirror plugin**，每个 plugin 内含一个 `TooltipProvider` 控制 toolbar 的显示/隐藏
2. **`TooltipProvider.update()` 只在 ProseMirror transaction 时触发**（节流 20ms）
3. 当用户从 editor A 点击到 editor B 时，**editor A 没有 ProseMirror transaction**，所以 editor A 的 `TooltipProvider.update()` 不会执行，toolbar 不会隐藏
4. `shouldShow` 回调中检查 `view.hasFocus()`，这个检查是正确的——但 **`shouldShow` 根本没被调用**，因为没有 transaction 触发 update

之前所有方案失败的原因：
- **CSS class 方案**：Crepe toolbar 用 `data-show` 属性 + `display: none` 控制，与我们的 CSS class 独立，互相冲突
- **轮询方案**：`setInterval` 每 100ms 检查 `view.hasFocus()`，但 `TooltipProvider` 在 20ms 节流内可能重新设置 `data-show="true"`
- **selectionchange/mousedown 方案**：这些 DOM 事件无法触发 ProseMirror plugin update

## 解决方案

**在 blur 时强制 dispatch 一个 ProseMirror transaction**，触发 `TooltipProvider.update()`，让 `shouldShow` 回调执行 `view.hasFocus()` 检查，从而正确隐藏 toolbar。

关键代码路径：
```
editor blur → dispatch(tr) → plugin.update() → tooltipProvider.update() → #onUpdate() → shouldShow(view) → view.hasFocus()=false → hide()
```

### 修改文件

**`src/components/MilkdownEditor.tsx`**：

1. 移除全局 `editorRegistry`、`syncToolbarVisibility`、`ensurePolling` 等轮询逻辑
2. 在获取 `editorView` 后，给每个 editor 的 DOM 添加 `blur` 事件监听
3. `blur` handler 中 dispatch 一个空 transaction（保持 selection 不变），强制触发 plugin update

```tsx
// 在 useEffect 中（获取 view 后）
const handleBlur = () => {
  view.dispatch(view.state.tr)
}
view.dom.addEventListener('blur', handleBlur)
// cleanup 中移除
```

**`src/styles/milkdown.css`**：
- 移除 `.milkdown-toolbar.milkdown-toolbar-hidden` 规则（不再需要）

### 验证

1. 打开包含多个步骤任务的页面
2. 在步骤 1 的 editor 中选中文本 → toolbar 显示
3. 点击步骤 2 的 editor → 步骤 1 的 toolbar 应立即隐藏
4. 在步骤 2 中选中文本 → 只有步骤 2 的 toolbar 显示
5. 点击 editor 外部 → toolbar 隐藏
