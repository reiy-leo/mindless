## 修复"新建人员"按钮无反应

**根因**：Tauri 2 的 IPC 不会自动把 camelCase 字段转成 snake_case。`src-tauri/src/commands/persons.rs` 里的 `create_person(name, english_name, nickname, remark, group_id, tag_ids)` 接收的是 snake_case，但 `src/lib/api.ts` 的 `createPerson` 把前端 camelCase 整个对象直接 `invoke` 出去，Rust 端参数全部缺失，调用静默失败。

**修复**：在 `src/lib/api.ts` 显式把 camelCase 字段重命名为 snake_case 再 invoke。
- `createPerson`：englishName→english_name, groupId→group_id, tagIds→tag_ids
- `updatePerson`：同上 + isPinned→is_pinned, isArchived→is_archived, sortOrder→sort_order
- `createPersonPhone` / `createPersonEmail` / `getPersonPhones` / `getPersonEmails`：personId→person_id

**教训 / 守则（mindless 项目）**：
- Tauri 2 的 invoke **不会** 自动 camelCase → snake_case 重命名。新加/修改 command 时必须前端 api.ts 显式映射。
- 如果之后又出现「点击某按钮没反应」，先 grep 那个 command 名，看 Rust 端参数命名，再看 api.ts 是否做了映射。

**顺手排查过但无需修改的**：updatePerson / updateList / updateNote / updatePersonGroup / subtasks / steps 全部已在上轮修正到位（这次实测时只是 createPerson 没改成）。Rust 端确认 persons.rs 的 create_person / update_person / get_person_phones / get_person_emails / create_person_phone / create_person_email / update_person_group 字段全是 snake_case。
